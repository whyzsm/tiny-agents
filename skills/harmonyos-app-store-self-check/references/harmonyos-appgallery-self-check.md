# HarmonyOS AppGallery 自检矩阵

这份矩阵是 `$harmonyos-app-store-self-check` 的工作资料，不是华为应用市场的官方承诺或法律意见。它把输入资料中可见的“上架护航”内容整理成可验证的证据项；对于审核规则、地区要求、当前 API/AGC 字段和账号能力，必须以当前官方文档或 AGC 控制台为准。

## AGC 实测与本地预检的边界

本矩阵的工程、隐私、权限、签名和 listing 项属于本地预检。AGC 的真实“上架自检”
是对上传后的发布包进行云端真机测试，至少包含 `兼容性`、`稳定性`、`功耗`、
`性能` 和 `UX` 五个维度。只有 AGC 软件包管理页面中“上架自检”列明确显示
`已达标`，才可以记录为 `AGC_READY`；“合法性 = 已达标”只表示包上传合法。

AGC 实测报告若显示 `检测中`、`待优化`、`执行失败`，分别记录为
`AGC_PENDING`、`AGC_NOT_READY`、`AGC_EXECUTION_FAILED`。未登录、未上传、未
启动自检、缺少报告或设备覆盖不全，都不能从本地 `READY` 推导出 `AGC_READY`。

## 证据状态

| 状态 | 含义 | 例子 |
|---|---|---|
| `PASS` | 已有可复核证据，且没有发现阻断项 | 脚本通过、release 构建成功、真机流程记录 |
| `FAIL` | 已发现不符合项目或发布门禁的事实 | 公开仓库含密码、声明了未使用的敏感权限 |
| `BLOCKED` | 需要用户、AGC 或真实设备才能继续 | 缺少签名材料、未登录 AGC、无可用真机 |
| `UNVERIFIED` | 尚未检查，不能推断结果 | 截图未提供、审核政策未确认 |
| `NOT_APPLICABLE` | 已按产品设备/功能范围判断不适用，并保留理由 | 未使用实况窗且证据清单记录了原因 |

## 检查矩阵

### 1. 工程与身份

| ID | 检查 | 证据 | 失败影响 |
|---|---|---|---|
| `META-1` | AppScope/app.json5 存在且有 bundleName、label、versionCode、versionName | 文件路径、字段值、资源引用 | `P0`：包身份或版本不可确认 |
| `META-2` | module.json5 有 mainElement、pages/路由注册、deviceTypes | 模块配置和 main_pages.json | `P1`：安装后可能无法启动或缺页 |
| `META-3` | target/compatible/compile SDK 与目标设备、AGC 支持范围相符 | build-profile.json5、官方版本资料 | `P1`：兼容性或上传校验失败 |
| `META-4` | 应用名称、图标、描述、版本与待上传 artifact 一致 | listing 文案、资源、artifact 元数据 | `P1`：信息不一致或误导审核 |

### 2. 隐私、权限与数据

| ID | 检查 | 证据 | 失败影响 |
|---|---|---|---|
| `PRIV-1` | 隐私政策可访问，说明收集范围、用途、存储、删除/清除、联系方式和更新方式 | 应用内/市场 URL、法律文件 | `P0`/`P1`：隐私材料缺失或不完整 |
| `PRIV-2` | 权限声明、运行时申请、用户可见说明与真实功能一致 | module.json5、Ability 代码、页面文案、隐私政策 | `P0`：越权或用途不透明 |
| `PRIV-3` | 权限拒绝、取消、不可用和数据清除路径有可见反馈 | 真机/模拟器记录、页面状态 | `P1`：用户无法理解或撤回处理 |
| `DATA-1` | 敏感数据不以明文或不必要的远端路径保存 | SQLite schema、媒体层、存储策略 | `P1`：泄露或合规风险 |
| `DATA-2` | 删除业务记录会同步处理派生索引和本地媒体 | repository、cleanup service、回归测试 | `P0`：用户无法真正删除隐私数据 |
| `DATA-3` | 第三方 SDK、网络、广告、支付、账号、儿童/未成年人、健康和位置能力按实际情况披露 | 依赖、源码、隐私政策、listing | `P0`/`P1`：材料与行为不一致 |

### 3. 签名、构建与发布包

| ID | 检查 | 证据 | 失败影响 |
|---|---|---|---|
| `SIGN-1` | 产物是目标 product 的 release HAP/APP，不是 debug 包 | hvigor 命令、产物路径、构建日志 | `P0`：无法作为发布包使用 |
| `SIGN-2` | AGC 证书、profile、keystore 与 bundle/权限/版本匹配 | AGC 或签名工具输出（只保留摘要） | `P0`：上传或安装校验失败 |
| `SIGN-3` | 证书、profile、p12、密码、token、home 路径未进入提交内容 | `git ls-files`、暂存区扫描、`.gitignore` | `P0`：密钥泄露，必须停止发布 |
| `SIGN-4` | release 构建可重复，依赖已锁定且无未说明本地模块 | lockfile、ohpm、hvigor 日志 | `P1`：构建不可复现 |
| `ARTIFACT-1` | 指定 `.app`/`.hap` 存在、可读取且摘要可复核 | 本地文件、大小、SHA-256 | `P0`：无法确认上传对象 |
| `ARTIFACT-2` | 指定发布包可解压并包含可识别的 HarmonyOS 元数据 | 本地压缩包成员清单 | `P0`/`P1`：产物可能损坏或布局异常 |

### 4. 功能、稳定性与体验

| ID | 检查 | 证据 | 失败影响 |
|---|---|---|---|
| `QA-1` | 冷启动、首次运行、升级/迁移、重启回显和异常恢复通过 | 手工 QA/自动化日志 | `P0`/`P1`：核心流程阻断或数据丢失 |
| `QA-2` | 核心 CRUD、导航、空/加载/错误/禁用状态可达且反馈清楚 | 页面路径、测试记录 | `P1`：审核演示或用户使用失败 |
| `QA-3` | 无障碍名称、触达区、长文本、屏幕/折叠/平板适配经过适用范围验证 | 设备截图、无障碍检查 | `P1`/`P2`：可用性风险 |
| `QA-4` | 没有虚构远端同步、作者、点赞、评论、推荐或未实现能力 | 页面文案、静态数据、截图 | `P0`：产品描述和真实能力不一致 |

### 5. 华为官方 UX 标准

华为官方 UX V30 的完整编号、等级、适用设备和标准要点见
`references/huawei-ux-guidelines-v30.md`。以下 ID 是本 Skill 的本地映射；每一项
都必须记录适用性和证据类型，不得把“代码存在”直接当成视觉或真机体验通过。

| ID 范围 | 对应官方内容 | 最低证据 | 失败/缺证据影响 |
|---|---|---|---|
| `UX-2.1.1.1` | 系统返回 | 真机/模拟器操作记录，必要时截图 | `P1`：必须项不符合或未验证 |
| `UX-2.1.2.1`、`UX-2.1.2.2` | 多尺寸布局、挖孔区适配 | 手机/折叠屏/平板横竖屏截图或设备记录 | `P1` |
| `UX-2.1.3.1`-`UX-2.1.3.4` | 手势冲突、时长、点击热区、滑动控件 | 源码线索 + 设备操作/测量记录 | `P1` |
| `UX-2.1.4.1`-`UX-2.1.4.3.4` | 视觉风格：对比度、字号、应用/界面图标、清晰度 | 资源尺寸、设计/截图证据、适用设备截图 | `P1`/`P2`，按官方等级 |
| `UX-2.1.5.1.*` | 层级、搜索、新建、编辑、共享元素、秩序感转场 | 真机/模拟器录屏或 AGC UX 详情 | `P2`，除非影响核心流程 |
| `UX-2.1.5.2.*` | 动效完整性和转场时长 | 设备录屏、时间戳或实现配置 | `P1`/`P2`，按官方等级 |
| `UX-2.1.5.3.*` | 启动、滑动跟手、过界、离手减速 | 设备操作记录或 AGC UX 详情 | `P1`/`P2`，按官方等级 |
| `UX-2.2.1`-`UX-2.2.7.2` | 导航条、通知、实况窗、多窗口/PiP、深色模式、状态栏、沉浸 | 适用设备的运行记录、截图和功能范围证据 | `P1`/`P2`，按官方等级 |

官方 UX 规则的使用边界：

1. `必须`、`推荐`、`强烈推荐`是华为文档中的等级，不能改写成“AGC 已通过”。
2. 对比度、字号、图标清晰度、手势时长、转场时长和跟手反馈属于观察/测量项；
   没有当前版本证据时只能记为 `UNVERIFIED`。
3. 只对项目声明的设备和实际使用的系统能力检查；不适用项要写明原因并记为
   `NOT_APPLICABLE`。设备覆盖不足时，AGC 结果仍保持 `UNVERIFIED`。
4. AGC 的 UX 页签问题要保留问题名称、影响机型、发生次数和说明文档，并在可能时
   映射到官方编号，例如典型手势时长对应 `2.1.3.2`。

### 华为官方设计理念

`references/huawei-design-concepts-v6.md` 是华为《设计理念》V6 的方向性参考，
不是 AGC 新增测试编号。对宽范围 UI/产品体验审查，单独输出以下三项，并关联
具体页面、控件、设备和证据：

| ID | 原则 | 审查重点 | 证据边界 |
|---|---|---|---|
| `DESIGN-ONE` | One / 以人为本 | 清晰易读、图标精确、色彩协调、层级明确、操作直觉 | 当前版本截图 + 核心流程设备记录 |
| `DESIGN-HARMONIOUS` | Harmonious / 平衡共生 | 视觉和交互语言协调，物理世界的熟悉隐喻服务于理解，不压过功能 | 页面截图 + 交互记录；不能凭主观审美判定 AGC 失败 |
| `DESIGN-UNIVERSE` | Universe / 多设备自然演化 | 多设备自适应；核心交互保持一致，并按屏幕、交互方式和场景做差异化 | 多设备截图/录屏 + 设备与系统版本 |

设计理念缺少当前版本证据时记为 `UNVERIFIED`，不适用的设备或能力要写明原因。
这些原则应与具体的 `UX-*` 控件和设备检查交叉引用，不能替代硬性 UX 阈值或 AGC
报告。

控件只在项目实际使用或产品范围适用时检查；没有当前版本行为证据记为

### 7. 华为官方元服务设计

当项目是元服务、配置了元服务入口/服务卡片，或 listing 声明元服务能力时，读取
`references/huawei-atomic-service-ux-v4.md`。普通应用不要套用元服务专属门禁。

| ID | 检查 | 最低证据 | 失败/缺证据影响 |
|---|---|---|---|
| `ATOMIC-1` | 元服务形态和适用范围明确；普通应用明确记录不适用 | product/module 配置、发布形态 | `P1`：发布范围无法确认 |
| `ATOMIC-2` | 负一屏、搜索、应用市场、桌面、标签/碰一碰等发现入口和一步直达链路 | 入口清单、当前包设备记录 | `P1` |
| `ATOMIC-3` | 无开屏、无重复加载，打开→加载→落地页→退出流程完整 | 当前版本录屏/设备记录 | `P1`/`P2` |
| `ATOMIC-4` | 名称、元服务图标、服务卡片和真实能力一致 | 资源、服务配置、截图 | `P1` |
| `ATOMIC-5` | 元服务胶囊/Menubar 避让，底部页签为 2-5 个且核心功能首屏可发现 | 页面截图、设备操作记录 | `P1` |
| `ATOMIC-6` | 华为账号静默登录、隐私/权限授权可控制可反悔，不自建误导性登录流程 | 授权链路、隐私材料、设备记录 | `P0`/`P1` |
| `ATOMIC-7` | 服务状态、服务消息、添加/收藏/移除管理链路 | 系统入口和当前包记录 | `P1` |
| `ATOMIC-8` | 元服务/服务卡片近场或远场分享，接收方可无安装打开或添加 | 双端设备记录 | `P1`/`UNVERIFIED` |
| `ATOMIC-9` | 等待、取消、失败、重试和自然语言反馈完整，避免广告打断 | 页面状态截图、设备记录 | `P1`/`P2` |

这些 `ATOMIC-*` 是本 Skill 的本地检查 ID，不是华为或 AGC 官方测试编号。静态配置
只能确认声明和资源存在，不能证明系统入口、胶囊、卡片、静默登录、分享和状态触达
已经在设备上正常运行。元服务本地通过不能生成 `AGC_READY`。

这些检查来自 `references/huawei-hmi-guidelines-v6.md` 的官方 HMI 页面树。它们
补充 UX V30 的通用手势规则，覆盖多输入设备和跨设备交互。只对项目声明或实际支持
的输入设备执行；需要操作的项目必须有当前包的设备证据。

| ID 范围 | 检查内容 | 最低证据 | 失败/缺证据影响 |
|---|---|---|---|
| `HMI-EVENT-1..9` | 悬浮、点击、双击、长按、拖拽、滚动、轻扫、缩放、旋转的跨输入归一 | 同一功能至少两种适用输入方式的对照记录 | `P1`/`UNVERIFIED` |
| `HMI-TOUCH-1..3` | 基础手势、系统手势冲突、反馈/误触/替代路径 | 触屏设备操作记录和必要的录屏 | `P1` |
| `HMI-CURSOR-1..3` | 光标语义、悬浮态、光标清晰度 | 平板/电脑当前版本截图或录屏 | `P1`/`P2` |
| `HMI-FOCUS-1..4` | 初始焦点、焦点组与遍历、可交互边界、焦点可见和位置记忆 | 键盘/遥控器/旋钮操作录屏 | `P1` |
| `HMI-MOUSE-1..3` | 左右键、滚轮/缩放、悬浮和拖拽反馈 | 鼠标设备操作记录 | `P1`/`P2` |
| `HMI-KEYBOARD-1..3` | 系统快捷键不冲突、焦点导航、编辑/常用快捷键 | 键盘操作记录和快捷键清单 | `P1` |
| `HMI-TOUCHPAD-1..3` | 基础手势、系统/边缘手势、自然滚动和离手反馈 | 触控板操作记录 | `P1`/`P2` |
| `HMI-DRAG-1..3`、`HMI-SELECT-1` | 拖拽生命周期、移动/复制、目标反馈、框选状态 | 当前包完整拖拽/框选流程记录 | `P1` |

没有目标设备或输入方式的证据只能记 `UNVERIFIED`；明确不支持的能力记录

### 10. 华为官方性能体验

这些检查来自 `references/huawei-performance-guidelines-v7.md` 的华为官方文档
V7 快照，不是 workshop 基线。先根据产品能力和声明设备选择适用规则，再为每条
规则提供当前包的设备测量；不能从源码、debug 构建或截图推导性能通过。

| ID 范围 | 检查内容 | 证据要求 | 失败影响 |
|---|---|---|---|
| `DELAY-1..12` | 启动、点击、滑动、折叠/展开、长视频/短视频响应和完成时延 | 设备性能追踪、AGC 性能报告或带时间戳的测量；记录单位、统计方式和样本数 | 规则不达标 `P1`；建议项 `P2` |
| `FPS-1..9` | 启动/滑动/转场丢帧、卡顿率、视频卡顿和音画同步 | 帧率/媒体性能工具导出，保留当前包和设备身份 | `P1`：性能体验或媒体播放不达标 |
| `CONTENT-1..3` | 黑白闪跳、占位符加载、滑动内容完整率 | 当前包设备录屏加性能时间戳或 AGC 报告 | `P1` |
| `MEMORY-1..3` | 后台/前台内存峰值和历史基线比较 | 内存分析工具、场景、峰值、历史基线及澄清说明 | `P2`：官方建议项 |
| `CPU-1` | 后台 CPU 峰值 `<2%` | CPU 分析工具、后台场景、设备和统计窗口 | `P1` |

本地证据 JSON 使用 `required_rule_ids` 明确适用范围；不支持的功能用
`not_applicable` 和原因记录，缺少结果保持 `UNVERIFIED`。运行
`scripts/validate_performance_evidence.py --strict` 时，失败或未验证均不能
作为本地性能门禁通过。该结果仍不能生成 `AGC_READY`。

## Workshop 可见资料映射

外部 `harmonyos-code-workshop` 可见章节提供了以下基线：

- 发布顺序：开发者注册 → AGC 创建应用 → 准备证书/profile → 签名打包 HAP/APP → 填写国家/地区、价格、隐私政策链接 → 提交审核。
- 安全合规：最小权限、敏感权限用途说明、隐私政策、应用描述与功能一致、涉及未成年人时提供相应保护。
- 构建参考：release HAP/APP 命令、CI 中不依赖 daemon、签名密码通过环境变量注入。
- 签名材料：`.p12`、`.csr`、`.cer`、`.p7b` 及 profile 的职责区分。

这些内容没有覆盖完整的当前 AGC 字段、地区法规、内容审核规则、账号资质或尺寸阈值。报告中必须标记这些缺口，不要把“资料里没有提到”写成“官方不要求”。

## Harmony Wardrobe 证据地图

识别到本项目（`io.wardrobe.tiny` / `衣不缺`）时，追加以下门禁：

1. 离线启动、保存、重启回显应在无网络状态下验证；当前产品不应声明网络同步，也不应新增 `INTERNET` 权限。
2. 衣物、穿搭、穿着记录、逛店和心愿数据写入本地 SQLite；照片先经媒体层复制到应用本地目录，数据库只保留本地 URI/path。
3. 删除记录必须同时验证数据库行、搜索索引和本地照片清理；失败时给用户可见错误，不得静默保留外部 URI。
4. 隐私政策和用户协议位于 `docs/legal/`；应用市场截图位于 `docs/appgallery/screenshots/`，只能作为当前版本证据，不自动等同于 AGC 已接受。
5. `build-profile.json5` 中的本机 `signingConfigs`、密码、证书/profile 和 `/Users/` 路径只能作为本地发布输入，不能进入仓库提交或共享报告。
6. 若需修改 UI，先读取 `docs/background/yibuque-design.md`；上架自检不应顺带改变产品视觉方向。
