# 华为 HarmonyOS 控件总览 V6 / Huawei HarmonyOS Controls Overview V6

这份参考来自华为开发者官方设计文档《概览》，用于在上架自检中识别页面控件类型，
再将控件映射到交互、视觉、可用性和设备适配检查。控件分类本身不代表应用已经
通过真机测试或 AGC 上架自检。

## 来源 / Source

- 文档：概览
- 版本：`V6`
- 官方链接：<https://developer.huawei.com/consumer/cn/doc/design-guides/general_overview-0000001929599380>
- 获取日期：`2026-07-28`

官方目录分为六类：`导航类`、`展示类`、`操作类`、`输入类`、`选择类`和`容器类`。

## 控件分类 / Control Taxonomy

### 导航类 / Navigation

| 控件 | 自检关注点 |
|---|---|
| 底部页签 | 一级导航、选中状态、导航条避让、设备宽度适配 |
| 子页签 | 同级内容切换、当前状态、横向空间和可触达性 |
| 标题栏 | 页面层级、返回入口、标题截断和状态栏融合 |
| 导航点 | 轮播/分页位置反馈、当前页可识别、滑动手势冲突 |

### 展示类 / Display

| 控件 | 自检关注点 |
|---|---|
| 文本 | 字号、对比度、长文本换行、无障碍语义 |
| 分隔器 | 层级和对比度，不承担主要交互 |
| 子标题 | 信息层级、字号和截断 |
| 进度条 | 当前进度、加载反馈、长时间任务状态 |
| 索引条 | 快速定位、触控热区、列表滚动反馈 |
| 滚动条 | 可见性、滚动范围和设备输入方式 |
| 新事件标记 | 未读状态、数量表达和不重复打扰 |
| 即时反馈 | 操作结果及时可见、成功/失败状态清楚 |
| 即时操作 | 反馈中的后续动作、触控热区和撤销路径 |
| 气泡提示 | 触发方式、位置、遮挡和消失时机 |
| 数据可视化 | 图例、刻度、颜色对比、空数据和异常数据 |
| 二维码 | 清晰度、扫描入口、内容安全和失败反馈 |
| 文本时钟 | 时间格式、刷新、字号和深色模式 |
| 图片 | 裁切、清晰度、加载失败、替代文本和版权 |
| 空白 | 空状态原因、下一步操作和不误导用户 |

### 操作类 / Operation

| 控件 | 自检关注点 |
|---|---|
| 按钮 | 点击热区、启用/禁用/加载状态、操作结果和防重复提交 |
| 下拉按钮 | 展开方向、选项可见性、点击外部关闭和键鼠适配 |
| 状态按钮 | 当前状态明确、状态切换反馈和可恢复性 |
| 操作块 | 主要操作优先级、触控范围和误触防护 |
| 工具栏 | 工具分组、图标语义、溢出处理和窗口宽度适配 |
| 核心操作栏 | 核心任务入口固定可见、不被导航条或键盘遮挡 |
| 菜单 | 层级、定位、选项反馈和系统返回行为 |
| 文本选择菜单 | 选择范围、复制/分享等操作、系统能力兼容 |

### 输入类 / Input

| 控件 | 自检关注点 |
|---|---|
| 文本框 | 标签/占位、键盘避让、输入校验、错误和清除反馈 |
| 搜索框 | 搜索转场、输入建议、空结果、取消和历史状态 |
| 数字加减 | 最小/最大值、步进、边界反馈和重复点击 |
| 图案锁 | 绘制轨迹、错误反馈、重试和安全遮蔽 |

### 选择类 / Selection

| 控件 | 自检关注点 |
|---|---|
| 勾选 | 多选语义、选中状态、批量操作和无障碍名称 |
| 开关 | 即时生效状态、开关反馈、权限/网络失败回滚 |
| 单选框 | 互斥关系、默认值、选中反馈和表单提交 |
| 评分条 | 评分范围、半星/精度、结果反馈和可读性 |
| 滑动条 | 拖动热区、数值反馈、边界和跟手体验 |
| 选择器 | 当前值、滚动选择、确认/取消和设备输入适配 |
| 分段按钮 | 同级模式切换、选中状态、内容保留和窄屏适配 |

### 容器类 / Container

| 控件 | 自检关注点 |
|---|---|
| 列表 | 加载、空、错误、分页/滚动、删除和多尺寸布局 |
| 弹出框 | 标题、按钮顺序、遮罩、返回/关闭、键盘和导航条避让 |
| 半模态面板 | 拖动/关闭手势、边界、层级、底部导航条和焦点恢复 |

## 使用规则 / Audit Rules

1. 先识别页面中实际使用的控件类别，再检查对应的官方 UX 标准；不要把未使用的
   控件当成缺陷，也不要因为控件名称相似就替换实现。
2. 控件应结合 `huawei-ux-guidelines-v30.md` 检查：文本/图片/图标关注视觉风格，
   按钮/开关/滑动条关注点击热区和手势，列表/弹出框/半模态关注导航、返回和窗口
   适配，输入控件关注键盘、错误和权限反馈。
3. 控件识别可以来自源码、截图、设计稿或运行页面；控件行为必须用当前版本的
   截图、设备操作记录或 AGC UX 报告证明。静态出现一个组件名不能证明交互达标。
4. 报告中记录 `control_category`、`control_name`、页面/路由、适用设备、证据类型
   和状态。缺少运行证据时使用 `UNVERIFIED`，明确不适用时使用
   `NOT_APPLICABLE` 并写理由。
