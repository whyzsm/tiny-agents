## 自检使用规则 / Audit Rules

1. 先从 `module.json5`、产品 listing 和项目文档确定声明设备类型，再判断官方标准
   是否适用；不要把所有设备标准无条件套到每个应用。
2. 对 `必须` 项，没有当前版本的证据只能是 `UNVERIFIED`。`PASS` 必须能指出证据
   文件、截图、命令、设备和时间。
3. 视觉风格项优先检查真实 UI 截图和资源：对比度、字号、图标尺寸/清晰度、光标
   清晰度不能从 AGC 历史报告或静态构建成功推导。
4. 手势、转场、滚动、导航条、深色模式、状态栏、窗口和通知优先用设备/模拟器执行
   记录；源码扫描只能作为线索。
5. 本参考不改变 AGC 结果边界：AGC `UX` 页签的警告/不通过和“上架自检”状态必须
   原样记录；官方文档参考只能生成本地 UX 风险或证据缺口。

## 证据清单格式 / Evidence Manifest

将清单保存为项目内的 `docs/qa/huawei-ux-evidence.json`，或通过
`--ux-evidence <path>` 指定其他路径。`standards` 不完整时，脚本会对缺失编号给出
`UNVERIFIED`，不会用 AGC 总体“通过”补齐：

```json
{
  "source": "Huawei 通用应用 UX 体验标准 V30",
  "target_devices": ["phone", "tablet"],
  "standards": [
    {
      "id": "2.1.4.1",
      "status": "PASS",
      "evidence": [
        "docs/qa/screenshots/phone-home.png",
        "docs/qa/contrast-review.md"
      ],
      "notes": "按当前版本截图核对正文和标题对比度。"
    },
    {
      "id": "2.2.3",
      "status": "NOT_APPLICABLE",
      "evidence": ["docs/qa/feature-scope.md"],
      "notes": "当前版本没有实况窗能力。"
    }
  ]
}
```

允许的状态为 `PASS`、`FAIL`、`UNVERIFIED` 和 `NOT_APPLICABLE`。`PASS` 必须有非空
证据引用；`NOT_APPLICABLE` 必须有书面理由。证据引用只证明审查材料存在，脚本不会
打开图片、操作设备或替代 AGC 云测。
